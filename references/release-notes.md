# 版本更新公告与迭代日志

这个文件用于在一轮 AI Coding 开发、测试、修复或产品迭代后，生成清楚的版本记录。

它解决的问题不是“写一篇好看的公告”，而是让人和 AI 都能快速知道：这版做了什么、为什么改、改到哪里、还有什么没做、下一步怎么接。

## 什么时候使用

当用户提到以下需求时使用：

- 版本更新公告；
- 更新说明；
- 发版总结；
- 迭代日志；
- 开发回顾；
- 测试记录；
- 下一版计划；
- 把这轮进度交给另一个 AI；
- 多个 AI 工具之间同步进度；
- 记录这次 AI Coding 学到了什么、改了什么、没改什么。

## 三类目标读者

生成前先判断目标读者。不要一种模板打天下。

### 1. 给 AI Coding 工具看的交接摘要

目标：让下一个 AI 工具快速接上，不重复读长上下文。

重点写：

- 当前项目状态；
- 当前版本号或阶段；
- 已完成内容；
- 文件结构/关键模块；
- 未完成内容；
- 已知问题；
- 下一步只做什么；
- 不能改什么；
- 停止条件。

不重点写：营销文案、情绪表达、长背景。

### 2. 给用户/平台/GitHub Release 看的版本公告

目标：让使用者知道这一版有什么变化，是否值得更新，怎么使用。

重点写：

- 新增能力；
- 改进点；
- 修复问题；
- 使用方式变化；
- 兼容性或注意事项；
- 下一步计划。

不重点写：内部纠结、无关开发细节、AI 对话过程。

### 3. 给开发者自己的迭代复盘

目标：帮助自己避免重复犯错，形成下次迭代策略。

重点写：

- 这轮目标；
- 实际完成；
- 走偏/返工点；
- 哪些反馈被采纳；
- 哪些建议被拒绝；
- 学到的偏好/约束；
- 下次要避免的问题。

不重点写：面向外部用户的宣传语。

## 版本记录生成原则

1. **不要流水账**：不要只写“改了 A、改了 B”。要说明为什么重要。
2. **新增/修改/修复/未做分开**：让读者一眼看到变化类型。
3. **区分事实和计划**：已完成是事实，下一步是计划，不要混在一起。
4. **记录没变的东西**：尤其是用户关心的功能、接口、样式、数据、边界没有改。
5. **记录验证方式**：至少写清楚这版怎么检查过，或还没验证什么。
6. **记录决策原因**：重大取舍要写“为什么这么做”。
7. **记录 AI 学到的偏好**：用户反复强调的偏好、禁区、风格要求，要写进复盘。
8. **避免暴露敏感信息**：不要写 API Key、Token、内部凭据、私密链接。
9. **不要复制别人的版本公告文案**：可以借鉴结构，不照搬表达。

## 信息采集清单

如果用户没有给足信息，最多问 3-5 个关键问题：

1. 这版版本号或阶段名是什么？
2. 这轮主要目标是什么？
3. 新增了什么？修复了什么？删除或延后了什么？
4. 哪些文件/模块变化最大？
5. 这版怎么验证过？还有什么没验证？
6. 下一步最应该做什么？
7. 这版有没有明确不能碰或保持不变的东西？

如果用户只是想快速生成，可以按“未知”标注缺失项，不要编造。

```markdown
# VibeGuard vX.Y.Z 更新说明

这版主要解决：[一句话说明这版解决什么问题]

## 新增

- ...

## 改进

- ...

## 修复

- ...

## 使用方式变化

- ...

## 兼容性/注意事项

- ...

## 如何验证

- ...

## 下一步计划

- ...
```

写作要求：

- 不要夸大；
- 不要写“史诗级升级”；
- 每条尽量说明对用户有什么用；
- 如果是内部结构优化，也要翻译成用户能理解的收益。

## 质量检查

输出版本记录前自查：

- 是否区分了已完成和下一步？
- 是否写清了为什么这版重要？
- 是否写了没改什么/不能改什么？
- 是否记录了验证情况？
- 是否避免泄露敏感信息？
- 是否能被另一个 AI 工具直接接上？
- 是否避免照搬参考文案？

## 示例表达

推荐：

```text
这版主要把“开工前怎么写清楚需求”从一段提示词，整理成了可复用的 brief 工作流。
```

```text
本轮没有新增复杂自动化，重点是把 spec 生成规则写清楚，避免小任务被做成大工程。
```

```text
下一步建议先验证在目标 Coding Agent 里的触发和输出效果，再决定是否继续加模板。
```

避免：

```text
本次完成全链路能力升级，显著提升研发效率。
```

```text
该版本实现了闭环式智能协同。
```

## 借鉴边界

可以借鉴的结构：

- 交接摘要；
- 文件/模块结构；
- 当前进度；
- 下一步；
- 迭代日志；
- 反馈决策记录；
- 开发回顾报告。

不要照搬：

- 他人的项目描述；
- 他人的痛点表述；
- 他人的宣传句；
- 他人的示例字段顺序，如果与 VibeGuard 目标不匹配。

VibeGuard 的版本公告核心不是“让 AI 记录一切”，而是让下一轮 AI 和用户快速知道：当前版本的事实、边界、验证、风险和下一步。
